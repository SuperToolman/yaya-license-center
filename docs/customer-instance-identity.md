# 客户实例身份与平台运维访问

## 业务流程

客户档案（联系人手机号）→订单与有效平台授权→创建平台实例→部署并自动应用许可证→客户手机号验证码登录。

运营平台从客户档案读取电话，规范化中国大陆手机号，生成两个受保护的环境变量：

| 变量 | 来源与用途 |
| --- | --- |
| `YAYA_PLATFORM_ADMIN_MOBILE` | 客户联系人电话，初始化“YaYa 超级管理员”的 mobile，state_code 为 86 |
| `YAYA_PLATFORM_INSTANCE_ID` | 当前平台实例 UUID，用于运维凭证及短信发送的实例范围校验 |

新建与未部署实例编辑自动注入，前端不可覆盖；手机号非法时拒绝保存。首次部署历史待部署记录时补入缺失变量；升级新镜像时保留既有实例身份，缺失则从客户档案补入。实例升级不允许手工覆盖这两个变量。

低代码平台在数据库迁移后事务初始化管理员：锁定固定管理员行，检查 `instance_delivery_state`，核对手机号未绑定其他用户，再更新手机号、移除该管理员既有密码登录凭据、写入持久化交付标记。失败整笔回滚。标记独立于可编辑的用户扩展字段，重启不会覆盖管理员后来修改的手机号或自定义密码。恢复备份沿用备份中的初始化标记。

客户档案电话后续变化不自动更换已部署实例的管理员；请使用平台内明确的管理员变更流程。系统不会自动给其他用户分配管理员权限。

## 短信发送

已交付实例沿用现有手机号用户查找、验证码生成、Valkey 冷却/次数限制和一次性消费逻辑。发送阶段使用实例 `BACKEND_INTERNAL_TOKEN` 请求运营平台 `/api/platform-instances/{id}/sms/send`，运营平台检查运行状态、有效客户授权和实例密钥，再使用现有阿里云短信配置发送。

不将阿里云 AccessKey 分发至客户容器。运营平台须已配置 `ALIYUN_ACCESS_KEY_ID`、`ALIYUN_ACCESS_KEY_SECRET`、`ALIYUN_SMS_SIGN_NAME`、`ALIYUN_SMS_LOGIN_TEMPLATE_CODE`；可选区域和验证码参数名沿用现有设置。中心额外限制每个手机号 60 秒一次、每小时 5 次，每实例每小时 50 次。失败也计入限额。验证码不写入审计。

独立开发环境没有实例标识时仍使用低代码自身的短信配置。离线包构建自检使用测试手机号和随机实例 UUID，不发送真实短信。

## 平台运维身份

入口：客户管理→客户详情→平台实例→更多→平台运维访问。

1. 运营平台超级管理员使用现有账号密码正常登录运营平台。
2. 填写 4–500 字访问原因，生成 60 秒内有效的一次性入口。
3. 入口在 URL fragment 携带凭证；客户页面立即清除 fragment，POST 到同源认证接口，凭证不进入 URL query 和 Referer。
4. 客户 API 使用独立实例密钥向许可配置中的运营平台兑换，原子标记已使用。原运营会话必须有效，用户必须启用且仍为 platform_admin。
5. 实例创建确定性的独立运维主体，绑定本地系统管理员角色。主体不是客户超级管理员，没有手机号、密码或本地登录凭据，不进入客户普通用户列表、批量密码初始化，也不能通过客户用户管理修改或删除。
6. BFF 生成最长 30 分钟、受中心到期时间约束的实例 JWT。JWT 保留运营用户标识和不透明运维会话，正常权限检查仍适用。
7. 每次后端请求实时回查运营会话与权限并记录方法、路径、时间；不记录请求正文、密码和凭证。中心不可达则拒绝运维请求。通信 WebSocket 每次客户端操作核验并审计，空闲连接每 15 秒核验并断开失效连接。
8. 客户平台退出登录会撤销该会话；运营平台退出、用户禁用、角色/密码变化会使后续核验失败。运营平台也可撤销某实例全部运维会话。已提交的后台业务任务不会因此自动回滚。

运维访问页可查看最近 100 条会话及 300 条事件。数据库只保存一次性凭证、运维会话和源运营会话的 SHA-256 摘要；审计保留真实运营主体、访问原因与目标实例。

## 生产与开发凭据

生产启动不再创建 `yaya/yaya`，并清除历史明文固定默认凭据；客户首次交付绑定时删除该管理员旧密码凭据。开发环境仅在无客户手机号配置时首次插入默认凭据，冲突不更新，不在每次启动重置用户资料或密码。
