# 客户平台实例：部署到当前环境 Docker

## 当前流程

客户 A 上线系统 → 新建平台实例 → 配置客户、实例名、容器名、域名、版本、Web/API 端口、业务环境变量 → 创建并部署 → 校验离线 ZIP 并导入镜像→ 创建 Docker 容器 → 健康检查。

不需要选择目标服务器，不依赖运维 Agent。版本包包含发布端构建并通过健康检查的完整离线镜像，客户实例部署使用 docker load 导入并启动，无需访问镜像仓库。版本管理页不再显示独立构建验证队列，构建队列 API、面板和执行器已移除。

## Docker 环境

API 使用当前环境的本地 Docker：Linux 为 `/var/run/docker.sock`，Windows 为 Docker Desktop 默认命名管道；要求 Docker daemon 运行 Linux 容器。忽略 DOCKER_HOST 与 DOCKER_CONTEXT，不接收远程地址。

前端通过 GET `/api/platform-runtime` 检测。CLI 缺失、服务关闭、权限不足或 Windows 容器模式均提示不可用；无 Docker 时只渲染提示与刷新按钮，不显示创建部署表单。服务端部署接口也重新探测，返回 503，不产生部署任务。

运营平台直接运行在宿主机时，安装 Docker CLI 并确保服务账号可访问本机 Docker。运营平台自身运行于 Docker 时，镜像已增加 Docker CLI，使用新增的覆盖文件连接宿主 Docker：

```bash
docker compose -f deploy/compose.yaml -f deploy/compose.docker.yaml up -d --build
```

覆盖文件将宿主 `/var/run/docker.sock` 挂给运营服务。这里只用于当前主机部署；没有挂载时页面提示不可连接。Docker 访问权限属于平台超级管理员能力，仅受信任管理员可上传离线镜像包和部署，不向普通运营用户开放。

## 实例配置

平台实例列表完整显示版本包 UUID，容器名和域名分列，不显示端口。容器名链接进入 `/ops/containers/containers?search=<容器名>`，域名在新标签页打开。状态使用 HeroUI Chip：待部署为 warning、部署中为 accent、运行中为 success、失败为 danger、归档为 default。操作列仅包含详情和更多图标，更多菜单使用点击触发并支持键盘操作，悬停不打开菜单，按实例状态显示部署记录、部署、编辑、归档。

Docker 各标签对应 `/ops/containers/{overview|containers|compose|images|networks|volumes|configuration}`，原 `/ops/containers` 保留为概述入口。容器搜索使用 `search` 查询参数，状态筛选使用 `state`；刷新、返回及切换标签保留 URL 中的搜索与筛选条件。

### 部署设置：镜像仓库与代理

“新建实例”左侧齿轮按钮打开设置，包含镜像仓库、代理两个标签。代理仅预留说明，无配置字段或保存接口。

镜像仓库连接和代理界面保留，仓库账号继续加密保存，但它们不参与离线镜像部署。无需登录仓库或设置默认仓库。加速器地址仅保存，不修改 Docker daemon，也不影响客户实例。管理接口仍限平台超级管理员。

- 选择已启用客户与已上传版本包 UUID，同版本不同构建仍可区分。
- 新建实例名称在选择版本包和所属客户后自动生成 `lowcode-<版本号>-<客户ID>`，输入框禁用且不显示必填标记；编辑已有实例时保留原名称。名称 1–80 字；容器名 2–63 位字母数字、点、下划线和短横线，必须以字母数字开头，全平台唯一。
- 新建表单不再手填容器名，服务端查询本机 Docker 的所有容器名称，并在立即写事务中检查全部实例预留名称，从 `实例名-1` 逐个递增，使用首个空闲编号。归档实例的名称仍视为占用；实例显示名称允许重复，端口仍需不同。超长名称截短前缀以保留编号并满足 63 字符限制。编辑及部署重试沿用已保存的容器名；显式传入容器名的旧 API 调用保持兼容。分配后若其他程序抢占名称，Docker 创建会报冲突，不覆盖外部容器。
- 域名填写完整 HTTP/HTTPS URL，例如 `https://customer.example.com`。用于 CORS 和安全 Cookie 配置，保存时不请求该地址。
- Web/API 端口 1024–65535，二者不同。所有未归档实例做交叉端口检查；Docker 自身也会检查实际宿主端口占用。端口公开映射到当前主机。
- 新建实例选择版本包后，合并该包的 `deployment.environment` 部署声明与 `imageEnvironment` 镜像快照，按名称去重展示全部环境配置。切换包会重置本次填写。值输入框以变量说明作为 placeholder；平台自动维护的配置使用 disabled，不要求填写。数据库默认名为 `yaya_low_code`，用户为 `yaya`；数据库密码、缓存密码、认证及内部服务密钥由 API 为每个实例自动生成并加密保存，编辑时保留已有值。未修改的镜像值及部署默认值不作为覆盖项提交；其他可选配置允许按需覆盖。已保存值不回显，留空保留原值。仅在部署声明和镜像快照都缺失时提示包缺少环境配置。接口仍以每行 KEY=value 传递覆盖项，值中等号原样保留。移除行仅取消本次覆盖，不删除已有变量。

环境变量使用 AES-256-GCM 加密保存，实例 UUID 为认证附加数据。密钥位于数据库同级 `.platform-environment.key`，Linux 创建权限 0600；备份和恢复必须同时包含 SQLite、这个密钥、平台版本包和生产数据卷。密钥丢失无法解密已有环境，禁止删除后自动生成替代密钥。Windows 请使用服务账号目录权限保护文件。

详情只返回已配置变量名，不回显密钥值。编辑时填写的变量合并覆盖，未填变量保留。当前不提供单项变量删除或运行中实例重建；已部署或已创建容器的配置不可修改，避免误用新的数据库密钥破坏已有数据。

域名 DNS 解析、反向代理路由和 HTTPS 证书由现有网关配置，本轮不会自动注册域名、申请证书或操作网关。域名指向本机后，需将对应域名流量转发至实例 Web/API 端口。平台内外部 WebSocket 地址应与低代码平台的现有部署要求一致。

## Docker 部署任务

POST `/api/platform-instances/{id}/deploy` 创建持久化任务，异步执行，不阻塞浏览器。创建页面自动调用部署；若保存成功后 Docker 失去连接，表单重试会沿用已有实例 ID，不重复创建。已有实例也可点击部署。

1. 读取实例加密环境，重新核对 ZIP 摘要和逐文件完整性、CRC、路径、包契约。
2. 校验完整离线 ZIP 与 image.tar 摘要，仅展开固定归档文件；匹配当前 Docker 架构，执行 docker image load，再核对镜像 ID 和架构。部署端不编译、不拉取镜像。
3. 保存镜像内容 ID，使用 --pull never 按配置容器名创建容器；不覆盖同名已有容器。每个实例创建 `yaya-<instance UUID>-postgres` 与 `yaya-<instance UUID>-state` 两个独立数据卷。
4. 环境通过临时权限 0600 的 env 文件交给 Docker，文件在任务结束删除。仅使用运营平台验签公钥，通过 docker cp 复制到停止状态容器；无需挂宿主临时路径，兼容 Docker Desktop 与运营平台容器化运行。签发私钥不进入客户容器。
5. 启动容器并检查内部 API `/healthz` 和 Web `/login`，随后自动写入该客户已签发的最新有效许可证，校验签名、有效期、客户授权版本及许可中心状态并确认激活。授权成功后才完成部署；不需要登录客户平台再次“更新平台签名”。授权失败会记录为部署失败，保留容器与数据卷。客户必须先完成订单授权交付；这里自动应用已有许可证，不替代订单签发流程。

状态：待部署 / 部署中 / 运行中 / 部署失败 / 已归档。运行中表示此次部署健康检查成功；目前尚无周期探测更新停止状态的控制循环，容器后续异常请查看容器监控，不能将此状态当作长期可用性保证。

页面部署记录显示阶段、受控日志和失败原因，每 3 秒刷新弹窗。失败时保留出错阶段，展示 Docker 子命令、退出码与 stderr 尾部（最多 2400 字符），去除 ANSI 控制序列并遮盖常见凭据赋值及 URL 用户密码。stdout 不保存；stderr 持续读取且仅保留有限尾部，避免长时间导入耗尽内存。诊断仅向平台超级管理员开放，发布镜像仍应经过审核。

API 重启会将未结束任务标记中断并将实例置为部署失败，保留已记录的容器 ID。已有容器禁止再次自动部署或归档，管理员先检查实际 Docker 资源；当前不实现运行中升级、重新创建、删除容器或数据恢复。

## 接口与迁移

所有接口都要求 platform_admin 员工会话，变更校验 Origin：

| 路径 | 行为 |
| --- | --- |
| GET /api/platform-runtime | 当前本地 Docker 探测 |
| GET/POST /api/platform-instances | 实例列表 / 创建配置 |
| GET /api/platform-instances/options | 客户和版本选项，无主机列表 |
| GET/PUT /api/platform-instances/{id} | 详情 / 编辑未部署配置 |
| POST /api/platform-instances/{id}/deploy | 当前 Docker 部署 |
| GET /api/platform-instances/{id}/deployments | 最近 20 条部署任务 |
| POST /api/platform-instances/{id}/archive | 归档未创建容器的配置 |

新增第 2 号迁移，不修改既有迁移。历史实例保留并自动生成容器名、移除主机关联，首次部署前编辑补全域名和加密环境即可。已有上传包保持不变。存在任何实例（包括归档）时客户不可删除。

## 2026-11-10：部署结果与实际运行状态分离

实例 API 返回独立 runtime（state、checkedAt、health、exitCode、message），status 保留部署结果/归档状态。容器绑定后列表优先显示实际运行状态，部署执行中仍显示部署中。支持 running/exited/created/paused/restarting/dead/removing/missing/mismatch/unknown；Docker 断连不再显示为部署失败，也不隐藏历史实例。仅完整 ID 与实例标签同时匹配的容器允许启动、停止和重启；保留保护规则、管理员权限、来源校验、expectedState 冲突检测、任务互斥及审计。

实例“更多操作”可直接打开容器详情与启停、容器日志。详情包含镜像、端口、创建时间、客户/实例关联、健康检查、退出码、数据卷和最近 30 次操作；部署记录仍保留独立入口。运行中并不代表应用业务就绪，未配置 Docker HEALTHCHECK 的镜像明确显示未配置。

API 启动将未完成部署和容器动作标记中断，并立即恢复实际容器状态核对；不会重复启动部署、重建容器或删除卷。缺失容器和异常绑定保留记录，需人工处理，不自动复用同名容器。详见 [状态与控制验收](./instance-runtime-e2e-2026-11-10.md)。

## 2026-11-10：新建实例分组与 Docker 网络配置

新建/编辑实例使用 HeroUI Card 分为基础信息、存储空间、网络配置、其他。桌面端版本包与客户同行，实例名称与容器名称同行；手机端自动改为单列。名称沿用自动生成规则。存储空间说明数据库和平台文件的两个独立持久卷，不提供容量配额设置。

网络模式位于端口之前，默认 bridge。管理员接口 `GET /api/platform-networks` 读取当前 Docker 已有的本地 bridge / macvlan 网络及子网；选择结果通过 `networkMode`、`networkName` 保存，部署前再次核对实际网络驱动并传入 `docker create --network`。不创建网络，不配置静态 IP。macvlan 需要提前在 Docker 环境创建并配置路由和宿主互通；当前 Windows Docker Desktop 的默认网络已验证，自定义 macvlan 未进行真实部署验收。

host 显示为禁用并说明原因：当前离线镜像包含数据库、缓存等固定端口服务，尚不能安全共享宿主网络。新增第 6 号迁移，历史实例默认记录为 bridge，不重建现有容器或删除数据卷。

验证：18 项后端交付测试、16 项实例页面测试、TypeScript 和相关 ESLint 检查通过。页面测试覆盖分组、同行布局、默认网络、子网显示和 macvlan 参数提交。
