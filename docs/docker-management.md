# Docker 容器工作区

更新：2026-11-11。

## 页面

入口 `/ops/containers` 默认概述，以现有运营平台视觉组件实现，不依赖 Linux 监控开关。支持 Windows Docker Desktop 与 Linux 本机 Docker 连接。Docker Desktop 展示其 Docker 引擎与虚拟机配置，不代表 Windows 物理主机监控。当前真实验收环境为 Windows Docker Desktop 29.9.2 / Linux 容器；Linux 真机仍需单独验收。

- 概述：所有、已启动、已停止、已暂停容器数；Compose 项目、镜像、网络与存储卷数；Docker system df 的已用/可回收空间。统计卡片可跳转对应标签。
- 容器：名称、镜像名称（按本地镜像标签解析不可变 ID）、状态、CPU、内存百分比和用量、网络 IP、发布端口、创建时间和日志。支持搜索、状态过滤和手动刷新；仅概述标签在页面可见时每 5 秒自动刷新，可关闭自动刷新，切换其他标签立即停止定时刷新。标签栏使用 HeroUI Tabs。
- 编排：按 Docker Compose 项目/服务标签展示已有项目及容器统计，不导入或编辑 Compose 文件。
- 镜像、网络、存储卷：读取实际 Docker 资源，不提供资源删除和磁盘清理。
- 配置：只读 Docker 版本、运行环境、架构、CPU 和内存，不修改 daemon 配置。

默认最多展示 200 个容器。总数来自当前 Docker，状态分组/编排统计只统计当前展示范围，超限有明确提示。采样失败时显示不可用，停止容器没有实时采样值，不伪装成 0。查询中旧值可能暂保留，查询失败不将旧列表继续展示为当前数据。

TCP 发布端口提供浏览器链接：0.0.0.0 / :: 使用当前页面主机名，明确绑定地址保留；IPv6 使用方括号。443/tcp 使用 HTTPS，其他 TCP 默认尝试 HTTP。端口映射不代表服务一定提供 HTTP；UDP 与未发布端口仅展示文本。域名网关和应用协议仍按实际部署配置。

## 状态操作与日志

状态按钮支持悬停、点击及键盘菜单。本迭代仅开放已绑定的平台客户容器：运行中可停止、重启，已退出或已创建可启动。其他动作不可用，所有写操作需确认。容器详情和实例更多操作提供同样的入口，操作不删除容器、不删除数据卷。

仅 platform_admin 可以读取资源、日志或操作容器。POST 必须提供受信任 Origin，目标必须是完整容器 ID，动作使用固定白名单。客户端同时提交 expectedState，执行前重新读取状态，目标变化返回冲突，不按名称重定向到其他容器。

动作首先在 `ops_container_actions` 持久记录并追加带操作者/目标/动作的运维审计，再启动后台执行。唯一索引防止同一容器并行任务；任务执行前复查会话、角色、保护规则与当前状态；完成后读取 Docker 实态验证并记录结果。API 重启把未结束任务标记 interrupted，并追加中断审计；启动后自动核对绑定容器的 Docker 状态，保存首次成功核对结果到任务 reconciliation，不将状态相同直接解释为任务成功，不自动重放。

保护规则：`com.yaya.protected=true` 标签、名称或镜像包含 yaya-operation-center、与当前控制平面 HOSTNAME 匹配的容器，或环境变量 `YAYA_DOCKER_PROTECTED_CONTAINERS` 的逗号分隔名称/完整 ID。自定义部署名称/镜像且不能通过 HOSTNAME 识别时，应显式配置保护列表。第三方容器仅可读取资源与日志，禁止写操作。写操作同时校验数据库 container_id 与 com.yaya.instance-id 标签，实例必须未归档且非部署中；提交和异步执行前均重新核对。本轮不开放删除容器/数据卷。

日志默认最近 200 行，历史查询最多 4 MiB，支持时间范围、输出类型和下载；实时日志通过 WebSocket 持续读取，支持暂停滚动与搜索。日志可能包含业务敏感信息，只授权管理员查看；不回显 Inspect 环境变量或容器命令。前端日志按纯文本展示。

## 接口

所有接口位于已有 `/api/ops` 鉴权/审计中间件内，本机 Docker 路径不受主机采集开关限制。

| 方法和路径 | 行为 |
| --- | --- |
| GET /api/ops/local/containers | 容器、实时采样、IP/端口和可用操作 |
| GET /api/ops/local/containers/{id} | 白名单详情、客户/实例关联、健康检查、退出码、挂载卷 |
| GET /api/ops/local/containers/{id}/actions | 最近 30 次操作及重启后核对结果 |
| GET /api/ops/local/inventory | 引擎配置、镜像、网络、卷和磁盘占用 |
| GET /api/ops/local/containers/{id}/logs | 最近 200 行日志 |
| POST /api/ops/local/containers/{id}/actions | 提交动作和 expectedState，返回 202 / taskId |
| GET /api/ops/local/actions/{id} | 查询任务状态和失败原因 |

新增迁移 `0003_container_actions.sql`，保留 0001/0002 原内容与校验和。Docker CLI 使用固定参数数组和当前本机连接，禁止从请求指定远程 daemon、脚本或任意命令。命令读写有输出上限和超时；权限隔离沿用当前直接本机 Docker 通路，本轮没有完成宿主执行服务的进程隔离改造。

## 2026-11-10 实例运行状态迭代

实例绑定容器由 API 启动后立即核对，随后每次核对完成间隔 5 秒重试。独立 `runtime_state` 保存实际状态、检查时间、健康检查和退出码，不覆盖部署结果。Docker 列表读取成功后才能判定容器缺失；Docker 无法连接或 inspect 失败为 unknown。标签不匹配为 mismatch，不按同名容器替换旧绑定。API 启动先清空旧快照，再核对，避免将进程重启前的缓存当作当前状态。

实例页面每 5 秒刷新记录和 Docker 可用性；Docker 失联保留实例列表，禁止新建/部署。容器资源其他 tabs 继续只手动刷新，仅概述自动每 5 秒刷新。容器基础详情采用手动刷新，操作结束主动刷新；后续资源监控标签提供独立 5 秒刷新开关，日志与终端按连接生命周期处理。

新增 delivery/0004_runtime_state.sql 和 ops/0004_action_reconciliation.sql；旧迁移未变更。真实验收、自动化验证与边界见 [本次验收记录](./instance-runtime-e2e-2026-11-10.md)。

## 2026-11-11：生产 Docker 版本与普通容器操作修复

线上 Docker Engine 最高支持 API 1.45，原直连传输硬编码 /v1.47 导致日志、Exec 和指标请求返回 HTTP 400。现在先通过不带版本前缀的 /version 获取服务端范围，选择服务端与客户端共同支持的 API（客户端上限 1.47），探测成功缓存 30 秒。无共同版本或探测失败时返回明确错误，不自动重放变更请求。

普通 Docker 容器的管理员启停和交互终端不再要求本平台创建记录或客户关联。带客户实例标签的容器仍需匹配完整 ID 和有效实例；归档、部署中或错配的客户容器仍不可操作。管理平台自身、显式保护标签及配置名单仍受保护，前端统一读取 terminalAllowed 控制列表按钮、详情按钮、终端标签和实际渲染。保留管理员会话、Origin、目标状态复查、互斥和审计。

恢复普通容器的启动、停止、重启、强制停止、暂停及恢复状态操作。终端依赖容器内存在 /bin/sh；无 Shell 的镜像会返回连接失败诊断。

此修复需要重新构建并发布运营平台 Web/API；无需升级服务器 Docker，也不需要重建客户容器或数据卷。当前本地验证不等于远程服务器已经更新。

本轮自动化验证：Rust 91 项通过；运维、交付与可观测性页面回归 34 项通过；另新增无客户关联普通容器从列表进入终端的专项测试通过。Docker API 1.45 传输模拟同时覆盖日志路径和 Exec Upgrade 握手。
