# 客户实例真实状态与容器控制验收

日期：2026-11-10。环境：Windows Docker Desktop 29.9.2，Linux 容器模式；运营 Web 8778、API 8779。

## 实现范围

1. 实例独立保存实际 Docker 状态，启动立即核对，之后每轮完成间隔 5 秒重试。部署成功记录不再代替容器实时状态。
2. 容器列表新增客户/平台实例关联；详情展示镜像、状态、端口、创建时间、健康检查、退出码和数据卷，不返回环境变量值或完整 Docker 配置。
3. 实例更多操作提供“容器详情与启停”和“容器日志”。日志最近 200 行，最多 512 KiB，清除 ANSI 色彩控制字符；部署失败记录仍单独保留。
4. 只对平台数据库完整容器 ID 与实例标签双匹配、未归档且非部署中的客户容器开放启动、停止、重启。平台管理员、受信任 Origin、目标保护、状态冲突、任务互斥、执行前再次校验和审计均在后端执行。
5. API 重启将运行中任务置为中断、记录审计并核对实际状态；保存首次成功核对结果，不自动重放，也不根据当前状态推断任务一定成功。

页面回归 31 项通过，覆盖实例日志→停止→任务结果→列表同步、Docker 断连仍展示实例、现有表单/部署流程、容器工作区及概述限定 5 秒自动刷新。TypeScript 和修改组件 ESLint 检查通过。

Docker 断连和容器删除分类通过自动化验证；没有为模拟这两种故障而关闭用户 Docker Desktop 或删除既有客户容器。中断恢复由数据库测试验证，真实 API 重启发生在操作任务完成后。该镜像未配置 Docker HEALTHCHECK，详情显示“未配置”；真实服务就绪另行请求 Web/API 验证。数据卷验收比较名称及挂载点，不等同于全库业务一致性检查或备份恢复演练。
