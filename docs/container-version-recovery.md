# 容器版本、恢复点与回退

本轮入口：客户管理 → 查看平台实例 → 更多 → **版本与恢复点**。已关联客户实例的容器详情也有同名入口。Web/API 继续使用单容器部署。

## 本轮交付范围

客户平台实例支持手动创建恢复点、目标平台包升级、失败恢复原容器、恢复历史版本、部署修订与任务历史。支持恢复点解密校验、下载加密 ZIP、删除历史恢复点及独立导出备份主密钥。

普通第三方容器尚未接入通用镜像切换表单；共享卷、bind mount、tmpfs、设备映射、特权容器不纳入本轮自动备份及升级。不会静默跳过不支持的存储。

## 部署清单

低代码项目 `deploy/platform-runtime.json` 描述 Web/API 内部端口、环境变量规则、持久化卷用途及目标路径。`scripts/package-platform.mjs` 将它与实际镜像 ENV 合并写入离线包 manifest 的 `deployment` 字段。运营平台在上传时验证，保存到版本元数据。

升级必须选择包含该清单的版本包。现有未携带清单的包可以继续作为现有记录保留，但不能作为升级目标；应重新执行打包脚本后上传。当前没有修改旧版本包原文或伪造清单。

清单示例：

```json
{
  "webPort": 8787,
  "apiPort": 8788,
  "volumes": [
    { "key": "database", "destination": "/var/lib/postgresql" },
    { "key": "platform-state", "destination": "/var/lib/yaya" }
  ],
  "environment": [
    { "name": "POSTGRES_PASSWORD", "required": true },
    { "name": "NEW_OPTION", "default": "enabled", "required": false }
  ]
}
```

同用途卷通过 key 关联，允许目标挂载路径变化。已有实例来自无清单的历史包时，只按完全相同的挂载路径匹配源卷，不推测数据用途。新用途创建空卷，目标不再使用的卷不挂载，原卷保留。卷拆分、合并、文件格式转换需要目标应用自己提供明确迁移实现；执行器不会猜测或复制数据到任意目录。

环境变量以目标声明为准：同名保留现值、新增使用目标默认值、必填缺失阻止停机；旧声明移除的变量从目标配置去掉。表单允许显式覆盖及移除，必填变量不能移除。平台验签公钥路径由控制平面重新注入。原数据库密码和加密密钥应保留在部署声明中，才能继承并读取克隆的数据。

## 运行流程

1. 事务内登记任务，绑定管理员、实例、完整源容器 ID 和幂等任务 UUID。
2. 与启停、终端和授权同步互斥。检查标签、保护规则、目标状态、独占卷、备份辅助镜像。
3. 升级时先验证离线 ZIP 摘要、逐文件契约和镜像架构，导入并锁定实际镜像 ID，再复查管理员会话与容器状态。
4. 加密保存源修订完整配置。优雅停止源容器，确认停止，再备份所有挂载卷；超过 Docker 停止等待时间会由 Docker 终止进程，因此实际持久数据仍需数据库自身的崩溃恢复能力。
5. 备份以 1 MiB 分块 AES-256-GCM 加密，每块绑定恢复点、卷序号和分块序号，包含加密结束标记，记录密文 SHA-256、大小。写完后重新解密校验，全部通过才成为 ready 恢复点。备份目录至少保留 256 MiB 空间余量，持续检查写入空间。
6. 为目标修订创建独立卷，从校验后的备份恢复。新应用的数据库迁移只接触新卷，不写入旧卷。
7. 根据目标镜像默认启动配置、目标环境及存储清单创建候选容器，保留实例端口、网络和资源配置，复制当前验签公钥。
8. 启动并验证 Web `/login`、API `/healthz`，再替换容器名称、更新实例绑定并同步当前授权。
9. 成功后记录新修订，保留旧容器及原卷，旧容器关闭自动重启。失败时停止候选容器并关闭自动重启，恢复源容器名称、重启策略和原运行状态。失败卷保留排查。

当前健康检查路径为平台约定路径，支持清单中的 Web/API 内部端口。不是任意第三方应用的健康探测器。

## 恢复与中断

主动恢复历史点会先备份当前版本，再使用历史配置、历史镜像和历史数据创建另一套新卷及新容器。历史点之后新增的数据不会出现在恢复后的应用里，但保存在恢复前创建的恢复点中，可以再恢复。历史镜像被外部删除时不会联网拉取，需先重新导入镜像。

API 重启把 queued/running/recovering 任务标记 attention，将未完成备份标记 failed。实例仍保持版本锁定。管理员点击“核对并恢复原修订”，服务端核对确切源/目标容器 ID、标签、任务归属后恢复源修订，不自动重放整个升级。恢复失败会保留锁与诊断，不能伪报完成。

任务中断时，原容器可能停机，必须先处理 attention。留存任务辅助容器在恢复原修订前清理；不删除客户卷，不猜测同名容器归属。

## 备份文件与密钥

- 数据目录：运营数据库同级 `container-recovery/<恢复点 UUID>/`，每个卷一个 `.ygcm` 文件。
- 配置快照在 SQLite 中加密保存，恢复点下载 ZIP 包含密文配置快照、文件清单和加密卷归档。
- 主密钥复用 `.platform-environment.key`；“导出备份密钥”为独立、需管理员来源校验并写审计的下载操作。应把密钥存到不同的受控位置；仅有 ZIP 而没有密钥无法恢复。
- 导出包暂未提供前端重新上传导入，也不包含镜像归档；跨环境灾难恢复仍需保存运营数据库、主密钥、平台离线包及恢复点文件。当前页面恢复使用本机已登记恢复点。
- 最近一个 ready 恢复点禁止删除；版本任务进行中或待核对时禁止删除。保留策略为手动，不自动清理历史镜像、旧容器和数据卷。
- 标准 tar 保留文件内容、权限、UID/GID 和链接。没有声称保留任意文件系统的原生快照、ACL、扩展属性或运行进程内存。

## 辅助镜像与环境

开发环境优先使用本机 `docker:27-cli` 镜像，只运行其中的 tar。也可以通过 `YAYA_BACKUP_HELPER_IMAGE` 指定已经存在的工具镜像。运行时不联网拉取。

运营平台生产 Dockerfile 增加 Alpine 工具根文件系统归档，缺少辅助镜像时导入为 `yaya-backup-helper:bundled`；辅助容器关闭网络、只读根目录，通过受限权限挂载指定卷。生产镜像构建需能获取基础镜像，客户运行时无需联网。

Windows Docker Desktop 使用相同 Docker 卷接口与辅助容器，不读取 Docker Desktop 内部 VM 磁盘路径。

## 数据结构与接口

交付迁移 8 新增 `container_revisions`、`container_recovery_points`、`container_version_tasks`，没有修改迁移 1–7。

| 接口 | 功能 |
| --- | --- |
| GET `/api/platform-instances/{id}/versions` | 修订、恢复点和任务 |
| POST `/api/platform-instances/{id}/version-preview` | 目标版本变量与卷差异 |
| POST `/api/platform-instances/{id}/version-tasks` | backup / upgrade / restore |
| POST `/api/platform-instances/{id}/version-reconcile` | 核对中断任务并恢复源修订 |
| POST `/api/platform-instances/{id}/recovery-points/{point}/verify` | 解密与摘要校验 |
| GET `/api/platform-instances/{id}/recovery-points/{point}/download` | 加密 ZIP 下载 |
| DELETE `/api/platform-instances/{id}/recovery-points/{point}` | 删除非受保护恢复点 |
| POST `/api/platform-recovery/key-export` | 单独导出备份主密钥 |

所有接口仅 platform_admin；变更校验 Origin。任务历史不返回环境变量值、密文快照或密钥。

## 验证

隔离数据库和 Docker 测试使用基于已有平台 Node 运行时的测试镜像、合成文件与独立卷，验证新增必填变量和第三个卷的升级、升级前数据恢复、升级后数据再次恢复，以及故意启动失败时恢复原容器。不是现有客户系统的生产升级，也不是 PostgreSQL 大版本迁移验证。具体结果记录在 `api/runtime/dev/lifecycle-e2e-result.json`。
