# 采购申请表单设计案例

## 需求与建模

示例对象：供应商档案、采购申请、采购明细。申请字段包括申请人、申请日期、供应商、采购原因、明细、申请总额；明细包括物料、数量、单价、小计。实际字段类型与属性必须查询当前组件合同。本例不给出可直接保存的 Schema。

先明确数量是否允许小数、币种和舍入规则、总额是否含税、明细至少几行、供应商删除后如何展示、谁可修改。不得仅在页面显示小计就认定后台汇总规则已实现。

## 配置步骤

1. 查询供应商档案并复用或创建，读取真实字段 ID。
2. 读取关联组件、数字、日期、成员、子表组件的当前合同；在实际支持范围内选型。
3. 先配置数量、单价等基础字段，再配置公式或汇总。公式使用平台语法，核实空值、除零、精度与依赖字段。
4. 配置供应商关联展示字段、普通回填和子表回填。区分来源字段和目标字段，按真实 ID 映射；子表映射需逐项核对双方子表及其子字段，不能只验证主表字段存在。
5. 必填、默认值、只读、显示条件等属性以具体组件合同为准。数字最小值不能大于最大值，自定义默认数值应在范围内；枚举选项的存储值须唯一。
6. 整体预检，确认后保存，再回读验证。

## 验收样例

检查一行与多行明细、空值、零值、边界数量、小数精度、关联对象不存在、重新选择供应商、修改字段后旧记录展示。若尚未实际提交测试，交付中明确“设计已保存，业务样例待执行”。如果当前能力无法实现汇总或联动，应保留明确待办，不能用静态默认值伪装成动态计算。
