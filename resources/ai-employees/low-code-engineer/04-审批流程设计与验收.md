# 采购审批流程设计与验收

## 业务规则

示例：提交 → 按采购总额分支 → 指定成员或角色审批 → 经办人补充信息 → 抄送。阈值、等于阈值走哪条分支、会签或或签、参与人、必填字段必须来自用户或客户制度；本例不规定实际金额和人员。

## 配置步骤

1. 创建或读取 workflow 表单。创建时已产生内置 process，不另建普通自动化代替审批。
2. 读取 workflow contract、现有 process 和当前 version，以该 version 作为保存时的 baseVersion。
3. 查询实际审批人、经办人和抄送人的成员/角色 UUID；不能传姓名代替 UUID。遇到同名先澄清。角色有效不代表配置后始终有可用成员，应核实运行时人员安排。
4. 逐个读取 approval、executor、copy、condition 等节点合同，只使用该流程允许的节点。审批 self 表示提交人；members/roles 使用明确人员或角色，会签 all、或签 any 的细节以合同为准。
5. 经办节点 requiredFieldIds 使用当前 workflow 表单中的真实字段。检查所有分支的连线、可达性、参与人与收敛关系，不把图能保存当作业务完整。
6. 完整预检 nodes/edges，修正问题后提交保存预览并确认。保存只修改图，保留绑定、名称、触发器和状态。

## 生效与验收

默认内置审批流为 enabled；保存已启用流程会立即影响后续提交，既有实例继续使用其原版本。保存不会提交申请或自动批准记录。回读新的流程版本及启用状态。

业务验收另覆盖阈值两侧与边界、多成员会签/或签、角色无成员、人员停用、经办必填、抄送和既有实例。驳回、回退、转交、动态主管、超时升级等须查询平台实际能力，不从本例推断支持。未执行真实申请时明确记录“未做业务运行验收”。
