# 低代码开发规范与合同查询

## 开始设计

先确认业务对象、主子关系、字段含义、必填规则、唯一性、金额精度、参与人和外部接口。影响业务结果的未知条件必须澄清；不要自行编造审批阈值、人员或接口。空应用和没有知识库都允许开始设计。

读取实际应用、表单 Schema、关联关系、自动化和审批定义。复用已有资源；维护资源 ID 清单，避免重试产生重复表单。名字可重复，引用必须使用工具返回的真实 ID。

## 查询产品事实

使用平台当前版本的组件目录与精确组件合同查询组件类型、默认属性、可写范围。使用自动化合同和节点合同查询变量、条件句、字段映射、HTTP 参数。审批设计额外查询 workflow contract。具体工具名以当前会话工具清单为准。

字段使用正式 Schema 的 id、type、label、布局和 props 等结构；不能根据自然语言名称猜类型。创建字段从组件默认配置开始，补充需求属性。类型定义存在不代表所有跨字段语义都已通过预检；仍须回读并按业务验收。

## 保存顺序

创建普通/流程表单时，设计与关联目标已明确则优先在 create_form 传可选 schema，一次确认完成创建和初始配置。schema 必须包含 fields 数组，可包含 columns、rows、pageProps；省略服务器生成的 formUuid，表单名以工具 name 为准。不传 schema 保持空表单创建。关联目标尚不存在或循环依赖时先创建所需资源，再用真实 ID 补配置。审批流程图独立配置。

基础表单 → 子表和关联目标 → 引用字段 → 自动化 → 审批流程。更新保留字段 ID、表单身份、无关配置和当前版本。先预检完整设计，修正诊断，再提交写操作的确认预览。版本冲突后重新读取，不直接重发旧设计。

平台写入走授权工具，禁止用文件、SQL、脚本、内部 HTTP 绕过确认。部分失败记录已成功资源和缺口，不擅自删除补偿。表单保存立即生效，没有额外发布环节。预检不会执行节点或测试外部接口。

## 交付

回读实际保存资源和版本，分别报告“已保存”“当前启用状态”“实际执行是否测试”。确认待处理、预检成功、JSON 方案都不能称为上线完成。未支持的行为如实列为缺口。
