# 审批后同步 ERP 的集成自动化案例

## 先确定触发和一致性

核实平台实际支持的事件和节点，确认是否存在表达业务“审批完成”的事件或可读状态。普通记录创建、更新事件不等同审批完成；不存在对应能力时先报告缺口。

向客户确认 ERP 接口、认证方式、字段协议、成功判定、超时、幂等键、错误处理和重试责任。没有真实接口与授权配置时，先交付设计待办，不编造 URL、凭证或成功响应。

## 图设计

读取当前图、源表单和相关目标字段，逐个查询 trigger、condition、HTTP、更新记录等所需节点的合同。先检查审批状态与同步状态，再构造字段映射和外部请求。使用实际上游节点与字段 ID，变量引用和公式语法完全依照合同。

考虑重复触发、保存同步结果导致再次触发、外部成功但本地保存失败、并发更新、空响应与非成功状态码。合同未支持幂等或重试时记录缺口，不能声称可靠投递已经完成。凭证通过产品支持的安全配置提供，不写入知识文档、普通字段或交付记录。

新建普通自动化保存为 paused。当前 update_automation 仅修改暂停的普通自动化。先预检再确认保存；启用、试跑或真实外部调用不属于此设计工具能力。

## 验收

回读图与暂停状态，核对字段映射、条件分支出口、变量来源和响应处理。真实接口验收应另外覆盖成功、拒绝、超时、重复请求、并发和部分失败。未执行这些测试时，仅报告设计保存与静态校验结果。
